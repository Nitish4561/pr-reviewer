## 🎯 Intent Agent Output

### Example 1: Feature Addition

```markdown
## 🎯 Intent Analysis

This PR adds OAuth 2.0 authentication to replace the existing custom authentication system. The change aims to improve security posture and enable SSO integration for enterprise customers.

### ✨ Change Type
**FEATURE**

### 📌 Primary Intent
Add OAuth 2.0 authentication flow with GitHub as the identity provider

### 💡 Business Goal
Improve security by leveraging industry-standard OAuth 2.0 and enable future SSO integrations for enterprise customers

### 🔍 Key Changes
- Implemented OAuth 2.0 authorization code flow
- Added token refresh mechanism with Redis caching
- Created new API endpoints for OAuth callbacks
- Updated user session management to use JWT tokens
- Modified database schema to store OAuth provider data

### 📦 Affected Areas
`authentication`, `API`, `database`, `session-management`

### 🟡 Risk Level
**MEDIUM**

### 🏗️ Architectural Impact
Introduces new external dependency on GitHub OAuth service. Requires database migration and affects all authentication-related endpoints. Changes are backwards-compatible with feature flag.
```

### Example 2: Bug Fix

```markdown
## 🎯 Intent Analysis

This PR fixes a critical race condition in the payment processing flow that caused duplicate charges when users clicked the submit button multiple times.

### 🐛 Change Type
**BUGFIX**

### 📌 Primary Intent
Prevent duplicate payment processing by implementing idempotency checks

### 💡 Business Goal
Eliminate duplicate charges that result in customer complaints and refund processing overhead

### 🔍 Key Changes
- Added idempotency key generation using UUID
- Implemented Redis-based request deduplication with 5-minute TTL
- Added loading state to payment submit button
- Included defensive checks in payment processor

### 📦 Affected Areas
`payments`, `UI`, `API`

### 🔴 Risk Level
**HIGH**

### 🏗️ Architectural Impact
Introduces Redis as a critical dependency for payment processing. All payment endpoints now require idempotency key validation. Deployment requires Redis to be available before rollout.
```

### Example 3: Refactoring

```markdown
## 🎯 Intent Analysis

This PR refactors the legacy Express.js routing system to use Next.js API routes, consolidating the API layer and improving maintainability.

### ♻️ Change Type
**REFACTOR**

### 📌 Primary Intent
Migrate from Express.js to Next.js API routes for unified framework

Reduce technical debt, simplify deployment architecture, and leverage Next.js ecosystem benefits including automatic API routing and middleware

### 🔍 Key Changes
- Converted 15 Express routes to Next.js API routes
- Migrated custom Express middleware to Next.js middleware
- Updated error handling to use Next.js error conventions
```

## 🔍 Code Quality Agent Output

### Example 1: Issues Found

```markdown
## 🔍 Code Quality Review

Found 3 issue(s) across 2 file(s), including critical issues.

### 📄 auth.js

🔴 **HIGH** (Line 42)
**Issue:** Token refresh logic can cause an infinite loop when OAuth provider returns 500 errors repeatedly
**Suggestion:** Implement exponential backoff with maximum retry limit (e.g., 3 retries with 1s, 2s, 4s delays)

🟡 **MEDIUM** (Line 156)
**Issue:** OAuth state parameter is not cryptographically secure (uses Math.random())
**Suggestion:** Replace with crypto.randomBytes(32).toString('hex') for CSRF protection

### 📄 api/payment.js

🚨 **BLOCKER** (Line 89)
**Issue:** Race condition possible when checking payment status before processing - no database transaction isolation
**Suggestion:** Wrap payment check and charge creation in a database transaction with SERIALIZABLE isolation level, or use database row locking (SELECT FOR UPDATE)
```

## 📊 Combined Multi-Agent Review

### Full Example: Feature PR

```markdown
# 🤖 Multi-Agent PR Review

*Generated by NirikshanAI Multi-Agent System*

---

## 🎯 Intent Analysis

This PR implements real-time notification system using WebSocket connections to replace the existing polling-based approach, improving user experience and reducing server load.

### ✨ Change Type
**FEATURE**

### 📌 Primary Intent
Add real-time notifications using WebSocket for instant user updates

### 💡 Business Goal
Improve user engagement with instant notifications and reduce server costs by eliminating frequent polling requests (currently ~1000 req/min)

### 🔍 Key Changes
- Implemented WebSocket server using Socket.io
- Created notification event emitter system
- Added client-side WebSocket connection handler
- Updated notification UI to display real-time updates
- Added fallback to polling for unsupported browsers

### 📦 Affected Areas
`notifications`, `websocket`, `backend`, `UI`

### 🟡 Risk Level
**MEDIUM**

### 🏗️ Architectural Impact
Introduces WebSocket server as a new service component. Requires load balancer configuration to support WebSocket upgrades. Connection state management needed for horizontal scaling.

---

## 🔍 Code Quality Review

Found 4 issue(s) across 3 file(s), including critical issues.

### 📄 server/websocket.js

🔴 **HIGH** (Line 67)
**Issue:** No authentication check before accepting WebSocket connections - any user can subscribe to any notification channel
**Suggestion:** Validate JWT token during WebSocket handshake and store user context. Reject unauthorized connections with 401 status.

🟡 **MEDIUM** (Line 142)
**Issue:** Memory leak potential - socket event listeners not cleaned up on disconnect
**Suggestion:** Add socket.removeAllListeners() in disconnect handler and implement proper cleanup for notification subscriptions

### 📄 client/notifications.js

🟡 **MEDIUM** (Line 34)
**Issue:** No exponential backoff for WebSocket reconnection - could overwhelm server during outages
**Suggestion:** Implement exponential backoff with max delay (1s → 2s → 4s → 8s → 16s max)

### 📄 server/events.js

🔵 **LOW** (Line 89)
**Issue:** Console.log used for debugging in production code
**Suggestion:** Replace with proper logger (winston/pino) or remove debug statements

---

*Powered by **NirikshanAI** Multi-Agent System*
```

1. **Intent Agent adds crucial context** that makes code quality reviews more meaningful
2. **Multi-agent output is more comprehensive** but well-organized
3. **Inline comments are more actionable** with context awareness
4. **Risk assessment helps prioritize** what needs attention first
5. **Change type classification** helps set reviewer expectations
